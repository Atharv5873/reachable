## 3. Three sentences per track

**Track 01, Agents That Act on Connected Data.** The agents rank findings by multi-hop
reachability, not severity: FalkorDB's `algo.SPpaths` finds the likeliest attack paths over
Cypher-derived `ATTACK_STEP` edges, and `algo.maxFlow` on a node-split layer finds the
smallest fix set that cuts them all. They choose those tools over MCP, and before anything
is recommended `simulate_fix` proves it on a `GRAPH.COPY` of the graph. Every hop on screen
can show the facts and the Cypher behind it.

**Track 02, Agent Memory and Coordination.** Memory lives in each tenant's graph next to
the infrastructure: episodic (verdicts carried, risk acceptances with expiry), semantic
(learned "this image was the way in" patterns), procedural (an analyst's correction becomes
a new playbook version). The agents never call each other; they hand off through the `Run`
node, and every step is an `AgentStep` the UI streams. On the rescan, memory cut the work
from 9 findings and 28 tool calls to 1 and 16, with the same verified fix set (Gate B).

**Track 03, Company Brain.** Teams, people, on-call slots, ADRs and tickets are in the same
graph as the assets, so a fix plan names the owning team, who is on call at the scan's
time, and the decision record that opened the exposure, with its approver and date. The
Q&A maps English to one fixed graph intent and answers with its sources. It even corrects a
wrong premise (port 22 vs 443) because it reads the ADR, not the question.

## 4. The questions a judge is most likely to ask

**Q: Why isn't CVSS good enough?**
CVSS scores a bug in isolation; risk depends on the path to it. Here, 14 of 6,862 findings
lie on any attack path, scattered between scanner ranks #1,487 and #5,581, and the same 9.8
CVE is critical on one host and irrelevant on another. Severity is a property of a node;
reachability is a property of paths.

**Q: Is the graph doing the work, or the LLM?**
The ablation: same agent, same model, same prompt and budget, with every FalkorDB tool
answering "unavailable". Path recall@10 goes from 100% to 0%, and the fix set stops
cutting anything. The model judges and explains; the graph finds the paths and the cut.
(Rule 3 says if it works without FalkorDB the graph is decoration: this is the test.)

**Q: Your NDCG is 1.00. Did you overfit, or is it circular?**
It is partly circular, and we say so next to the number: our ranker and the ground truth
both define importance as weighted reachability, so 1.00 checks the derivation, not a
discovery. That is why we lead with structural metrics that cannot be won by sharing a
definition: path recall (100% vs 0-10%), decoys (0% vs smart_score's 33%), paths cut per
fix (1.16 = the oracle's min cut). Plus: three held-out v2 scans, never looked at while
building, score the same; the oracle is independent networkx over raw data; and
`test_eval_leakage.py` proves the ranker never reads labels and the baselines never see
paths, memory or tiers. A tier-blind version of our ranker scores 0.95, so the tiers are
tested too.

**Q (likely follow-up): Isn't the data synthetic, so you designed the answer?**
Yes, it is synthetic (the rules allow it, and real estates are private), and that is the
honest limit. Two things keep it from being circular: the attack logic is one written spec
(`attack_rules.py`) implemented twice, Cypher and networkx, and a test asserts identical
path sets; and the baselines get the same data with every hint we could find removed. The
next real test is a differently generated estate.
